# AGENTS.md

Repo conventions for create-nabin-app. What it is for: [PRD.md](PRD.md). How it is built:
[SPEC.md](SPEC.md). The flag contract lives in the CLI's own `--help` (`src/cli.ts`).

## Commands

All tasks go through the [justfile](justfile). Run `just` to list recipes.

- `just check`: Biome, typecheck, unit tests. Must pass before a commit.
- `just e2e [case ...]`: scaffold every stack for real, then run each generated project's
  own `just check`, `just build` and `just dev` (plus /api/health with --api). Run it after touching
  `templates/`, `src/generate/`, or `src/versions.ts`. Needs network; takes minutes.
- `just run <dir> [flags]`: run the CLI from source.
- `just refresh-shadcn`: regenerate the vendored shadcn layers from upstream.
- `just build`: compile `src/` to `dist/` for the published bin.
- Releasing to npm: [docs/releasing.md](docs/releasing.md). Never publish from a dirty
  tree or skip `just e2e` before a release.

## Layout

- `src/cli.ts`: argv parsing, help text, output, exit codes. The only file that does I/O
  for the user.
- `src/plan.ts`: flags to a `Plan`. Pure. Feature list, defaults and conflicts live here.
- `src/scaffold.ts`: builds the in-memory file tree, writes it, installs, commits.
- `src/generate/`: files whose content depends on the plan (manifests, configs,
  providers, start page, AGENTS.md, justfile, ADR).
- `src/versions.ts`: every dependency range the scaffolder writes. Nowhere else.
- `templates/<layer>/`: static files copied as layers. `{{name}}`-style placeholders are
  filled only for known keys.
- `templates/shadcn-*`: generated by `scripts/refresh-shadcn.sh`. Never hand-edit; change
  the script.
- `test/*.test.ts`: unit tests (`node --test`). `test/e2e.sh`: the real-surface suite.

## Rules

- The CLI never prompts. Every choice is a flag; `--json` output and exit codes
  (0 ok, 1 step failed, 2 usage) are a contract agents depend on.
- A generated project must pass its own `just check` and `just build` with no edits.
  Generated source is emitted already formatted for its Biome config; `just e2e` is the
  proof, and reading templates is not.
- Adding a feature: add it to `FEATURES` in `src/plan.ts`, wire its dependencies and files
  in `src/generate/web.ts`, add its convention line in `src/generate/docs.ts`, and add an
  e2e case that enables it.
- Bumping versions: edit `src/versions.ts` only, keep lower bounds at `.0` patches (pnpm's
  minimumReleaseAge must be able to pick a mature release), then `just e2e`.
- `biome.json` here equals the config generated for shadcn projects; a unit test enforces
  it. Change `biomeJson()` and regenerate, never the file alone.
